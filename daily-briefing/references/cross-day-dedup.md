# 跨天话题去重方法（v3）

## 问题背景

每日简报连续出多次后，同一话题容易重复出现。原因：去重依赖 agent 脑记或 session_search，不可靠。解决方案：文件化话题日志 + 6 步强制工作流。

## 完整工作流

### Step 0 — 日期（防 AI 猜错）

```bash
date +%Y-%m-%d
```

AI 推算日期经常出错（如 6/12 写成了 6/13）。系统时钟是最可靠的日期源。同一天多次生成自动覆盖同名文件。

### 数据源：文件代替对话搜索

每次生成后，将 9 条 topic+event 写入 `references/YYYY-MM-DD-topics.md`。次次 Step 1 读最近 3 天的文件，不依赖 session_search。

文件格式：
```markdown
# 2026-06-12 简报话题

AI | 标题摘要 | 话题: xxx | 事件: xxx
国际 | 标题摘要 | 话题: xxx | 事件: xxx
金融 | 标题摘要 | 话题: xxx | 事件: xxx
```

### Step 1 — 查历史黑名单

```bash
ls -t references/*-topics.md | head -3
```

提取每条的话题+事件，整理为黑名单：`话题: xxx | 事件: xxx`

### Step 2 — 抓取新闻

`python3 scripts/fetch_sources.py` 输出 JSON Lines。

### Step 3 — 选话题（粒度：话题+事件）

| 场景 | 判断 |
|------|------|
| 话题+事件都匹配 | 换掉（炒冷饭） |
| 话题匹配但事件不同 | 放行（新进展） |
| 话题不匹配 | 放行（新话题） |

连续演进话题（如伊朗局势）每天选不同子事件，同类目不连续超 2 天。

### Step 4 — 双检查

1. **话题去重**：9 条 topic+event vs 黑名单
2. **格式自检**：emoji 是 🤖🌐💰（不是旧版 🇨🇳），无链接（不是 `🔗 URL` 格式），出处用【】

### Step 5 — 保存 3 个文件

| 文件 | 用途 |
|------|------|
| `YYYY-MM-DD-topics.md` | 供 Step 1 去重 |
| `YYYY-MM-DD-audit.md` | 纯内容存档（不含 URL） |
| `YYYY-MM-DD-links.md` | 9 条原文 URL 链接 |

## 常见踩坑记录

1. **忘了查历史** — 6/11 CVPR 重复直接原因。改为文件化后 Step 1 读文件代替 session_search，更稳定
2. **同一事件不同来源** — 6/9 国际第 2 第 3 条（AP 和 Guardian 都报同一件事）。修复：同类目内 3 条必须是 3 个不同事件
3. **同一话题不同角度误杀** — 伊朗冲突每天不同子事件不应算重复。修复：检查粒度从"话题"改为"话题+事件"
4. **依赖 session 记录** — session_search 依赖对话记录是否还在、FTS5 能否命中。改为读文件更可靠
